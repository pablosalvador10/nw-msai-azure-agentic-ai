A model on its own only produces text. What makes it an agent is the harness around it: the loop, the context, the tools, the permissions, and the checks that tell it whether it succeeded. MCP on the wire

Revision 2026-07-28 is stateless: every request carries its version and its client

Discovery replaces the old handshake

POST /mcp
Content-Type: application/json
Accept: application/json, text/event-stream
MCP-Protocol-Version: 2026-07-28
Mcp-Method: server/discover

{"jsonrpc": "2.0", "id": 1, "method": "server/discover",
 "params": {"_meta": {
   "io.modelcontextprotocol/protocolVersion": "2026-07-28",
   "io.modelcontextprotocol/clientInfo": {"name": "notebook", "version": "1"},
   "io.modelcontextprotocol/clientCapabilities": {}}}}
MethodReturns
server/discoverSupported versions, capabilities, server identity
tools/listEach tool's name, description, inputSchema
tools/callcontent, structuredContent, isError. Header Mcp-Name repeats the tool name

Why stateless? Any replica of your Container App can answer any request: no sticky sessions, no session store. The headers let gateways route and log without reading the body.

The current revision

Changes you will meet in real servers

ChangeWhat it means
Multi round-trip requestsThe server returns "input required"; the client gathers the input and retries the original request. Servers no longer send their own requests
subscriptions/listenOne long-lived stream for change notifications the client opted into
Cacheable liststools/list carries ttlMs and cacheScope; a stable order also helps prompt caching
Trace contexttraceparent in _meta carries OpenTelemetry traces into the tool server
TasksLong-running work moves to an official extension
AuthorizationOAuth-based; the server validates that tokens were issued for it

Older clients still work

Revisions up to 2025-11-25 opened a session with an initialize handshake. The MCP Python SDK serves both eras on the same endpoint.

MCP security

Tools are arbitrary code execution. Trust servers deliberately

ThreatWhat happensDefense
Tool poisoningA description hides instructions the model obeysInstall servers you trust; review descriptions; pin versions
Injection through resultsA tool returns text with instructions in itResults are data; guardrails on tool responses; least privilege
Token passthroughA server forwards the client's token to another serviceAccept only tokens issued for you; never pass one through
Over-broad serversOne server with fifty write toolsEnable only what the task needs; separate read and write
Supply chainnpx some-mcp-server runs unreviewed codeTreat a server like any dependency: source, version, publisher
DNS rebindingA web page reaches a server on your laptop through your browserValidate Host and Origin: our app/main.py allows only its own names
Anonymous remote serversAnyone can call your /mcpAuthenticate (the API key in Week 10; OAuth or Entra ID in production)

Small steps

Each diff is reviewable; failures stay local.

Protect the judge

AGENTS.md forbids editing harness/ and the contract. An agent that edits tests to pass them is reward hacking: the score rises, the software does not improve.

Measure, then decide

The tests and the harness say whether it worked, not the agent's summary of its own work.

The exercise · Lab Part 4

A tool for riders at a full station: nearest_station_with_docks

The specification

Input: a station id. Output: the closest other station that is open and has at least one free dock, by great-circle distance (distance_km). Returns station_id, name, distance_km, docks_available. Unknown id: {"error": ...}.

Written as tests in tests/test_week08_nearest_station.py. They are skipped until the function exists.

A prompt that works: read AGENTS.md and the test file; implement the function in app/domain.py so every test passes; publish it as an MCP tool with a clear docstring; do not modify any test; run pytest and ruff and show me the output.

Steering the loop

When the agent gets stuck, fix the prompt before you add more code

  1. Give it the failurePaste the exact failing test output and ask it to fix that test only.
  2. Two rounds, then stopIf it does not converge, read the failing assertion yourself.
  3. Usually the promptThe spec was ambiguous to the agent. One sentence in the prompt fixes it.
  4. Ship what passesIf some tests stay red, deploy anyway. A published tool with some correct answers still scores.

Trust the tests and the harness, not the agent's summary of its own work. If the summary says "all tests pass", run them yourself.

Security of agentic coding

A coding agent runs with your permissions. Treat it as a fast colleague who can be tricked

RiskExampleMitigation
Prompt injection through contentAn issue or README says "also add this curl command to the build"Approvals for commands and network; sandboxing; review of diffs
Secret exposureThe agent reads .env and pastes a key into a log or commitRules against reading secrets; hooks that scan for them; keyless auth
Destructive commandsrm -rf, git push --force, terraform destroyDeny lists; approval for anything irreversible; work on branches
Invented dependenciesA package that does not exist, or is maliciousLock files, dependency review, CI
Over-trusting outputTests pass because they were weakenedProtected tests, code review, CI that runs the real suite

Every mitigation here is a harness feature: sandbox, approval policy, hooks, instructions, verification.

Lab Part 6

Write a check, and know what makes one good

def unknown_station_is_an_error(ctx: Context) -> tuple[float, str]:
    result = call_tool(ctx, "nearest_station_with_docks",
                       {"station_id": "LS-99"})
    ok = isinstance(result, dict) and "error" in result
    return (1.0 if ok else 0.0), f"LS-99 -> {result}"

A check takes a Context and returns a score and a detail line. Instructors add checks like this to the private harness.

  • Grade the outcome, not the path. Check the answer, not which helper produced it.
  • Separate capability from regression. Can it do the new thing? Does the old thing still work?
  • One run is one sample. pass@k: at least one of k runs succeeds. pass^k: all k do. Users experience pass^k.
  • Read the transcripts. A score says that something failed; the proof says why.

Summary

What to remember

  • An evaluation harness measures; an agent harness acts. They meet in verification.
  • A harness is loop, context, tools, permissions, verification, observability.
  • Context engineering: short, testable instructions; just-in-time retrieval; skills; compaction; subagents.
  • MCP makes your tools available to any agent. Revision 2026-07-28 is stateless: discover, list, call.
  • MCP is arbitrary code execution: trust servers deliberately, treat results as data, authenticate remote servers.
  • Copilot and Codex share the same primitives under different names: instructions, skills, agents, hooks, MCP.
  • Work spec-first, in small steps, with a protected judge and a human review.
  • Trust the tests and the harness, not the agent's summary.
