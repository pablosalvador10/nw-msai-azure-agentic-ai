Your first three steps

  1. Set up onceFollow the setup guide, then run the setup notebook. Finish with a deployed URL that responds to the harness.
  2. Review an unfamiliar toolIf Terraform, HTTP APIs, containers, identity or the harness are new, read the Foundations primers. Use the Foundations overview to choose a practice notebook.

What counts as finished?

  1. Understand one failureRun the weekly harness and inspect the failed exchanges. Change one thing in the service; do not hard-code public answers.
  2. Keep the contract and earlier work intactRun the offline tests and score the current week. In-process scoring runs your local service code; it is not a deployment and can still call real models unless offline mode is selected.
  3. Deploy and check the deployed URLUse the main lab's deployment steps. Confirm the version and student identity, then check the current and earlier weeks on that URL.
  4. Submit the URL, not the notebookFollow the week's overview for its deadline and evidence. Keep the service available until grading finishes. Never put API keys, environment files or reports in public commits.

A teaching simulation, not a live business. Station availability comes from a fixed snapshot. Credit and maintenance tools return simulated action records; they do not move money or create tickets in an external system. Read the handbook for policy and the domain code for deterministic rules.
