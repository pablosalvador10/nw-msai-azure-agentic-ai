Your course agentsFive Copilot agents that know this course. When you are stuck, they tell you where you are, what to do next, and why.

This course uses tools you may never have touched: a terminal, Azure, Terraform, a harness that scores your work. You do not have to work them out alone. The course ships five agents inside VS Code's Copilot Chat. Each one knows the course materials and has one job. Start with the FY26 Guide. Tell it where you are, even if all you can say is "I am lost", and it gives you one next step.

If you remember one thing. Open Chat, pick FY26 Guide, and say where you are. The rest of this page explains how, and how to get the most out of the other four.

What an agent is, in one minute

A Copilot agent is the chat model you already know, plus three things: instructions that give it one job, tools that let it look at your files and run commands, and skills it loads when your question needs them. The agent is the same model; the job is what makes it useful.

One job each

A narrow job gives sharper answers and safer actions. The Guide only routes; the Tutor only teaches; the Deploy Doctor only deploys and diagnoses.

Grounded in the course

They read the week's README, lecture notes, lab and your harness report before they answer, so their advice matches what you are graded on.

Plain files you can read

Each agent is one Markdown file in .github/agents/; each skill is a folder in .github/skills/. Open them: they are short.

You will build this pattern yourself. In Week 7 your service routes a support case to specialist agents, the way the Guide routes you. In Week 8 you write instructions for a coding agent in fy26/AGENTS.md. Reading the five agent files now is a preview of both weeks.

Before the first time

Do this once. After that, the five steps in the next section are all you need, every time. If any step here fails, go to If the agents do not appear.

  1. Get CopilotVerified students get Copilot Student free through GitHub Education. Approval and activation can take a few days, so apply in the first week. Copilot Free also works, with monthly limits.
  2. Sign in in VS CodeInstall VS Code. The first time you use Chat, it asks you to sign in with GitHub: use the account that has Copilot.
  3. Open the fy26 folderClone the course (Setup, step 2). Then File, Open Folder, and pick the fy26 folder inside it. If VS Code asks whether to trust the folder or its parent, trust them: the agents live one level up, in .github/.
  4. Check the listOpen Chat, open the Agent dropdown, and look for the five FY26 agents. Then ask the Guide your first question.

You do not need to finish Setup first. The agents need only VS Code, Copilot and the cloned course. If a later step of Setup fails, ask the FY26 Setup Doctor: it checks each step with you, in order.

What the Agent dropdown shows

The dropdown lists VS Code's built-in agents and the agents this repository adds. The five course agents all start with FY26, so they are easy to spot.

Pick one before you type. The placeholder text in the message box tells you what that agent wants to hear: the Setup Doctor, for example, asks for "Your OS and the step or error where you are stuck".

You can switch agents in the middle of a chat. If the new agent seems to miss the context, restate the week and the problem in one line. When the topic changes completely, start a new chat.

The five agents

What each one is for, what to say to it, and where its job stops. Use the Copy buttons to paste a prompt into Chat, then edit it to fit your situation.

FY26 Guide

The front desk. Start here when you are lost.

Read-only

Ask it when

  • You are new, or back after a break
  • You do not know what to do next
  • You are not sure which agent you need

What it does

  • Checks, without changing anything: the course folder, the Python environment, your Azure sign-in, your infrastructure, .env, and whether your URL answers
  • Replies in three parts: Where you are, Your next step, Who takes it from here

Try saying

I am lost.

I finished setup. What do I do for Week 6?

My URL stopped working and the deadline is tomorrow. Where do I start?

Where its job stops

  • It does not change files or Azure; the specialists do that, with your consent
  • It does not do the lab for you

FY26 Setup Doctor

Gets your laptop and your Azure environment working, one step at a time.

Asks before changing Azure

Ask it when

  • Installing uv, the Azure CLI, Terraform or Git
  • uv sync fails, or the notebook kernel is missing
  • az login, Terraform or .env give you an error
  • Your first deploy

What it does

  • Checks each setup step in order and stops at the first one that fails
  • Explains the error and the fix; runs setup commands after you approve them
  • Ends every reply with a status line, for example Setup: tools OK · venv OK · signed in OK · infra MISSING -> next: terraform apply

Try saying

I am on Windows and uv sync fails with a certificate error. What should I check first?

terraform apply stopped with AuthorizationFailed. What does that mean and what do I ask for?

The kernel ".venv (Python 3.12)" is not in the list for setup.ipynb.

Where its job stops

  • It never destroys resources or deletes your files unless you ask and confirm after it explains the consequence
  • It never guesses a subscription, tenant or region: it reads them, or asks you

FY26 Lab Tutor

Explains the ideas and coaches you to a better score. The code stays yours.

Explains; you write the code

Ask it when

  • A concept in the lecture or lab is unclear
  • A harness check fails and you do not see why
  • You want to raise a score and do not know where to look

What it does

  • Explains from first principles, using the week's lecture notes and lab, and links the section it used
  • Reads your newest harness report and names the pattern the failures share
  • Hints one rung at a time: a question about the evidence, then the concept, then the file and function, then a small example on a different problem
  • Ends with one next step that takes under 15 minutes

Try saying

Week 5. Explain structured output as if I had never seen it, then point me to the lab part that uses it.

Week 6. My newest report shows w06.ask.citations as PART. What do the failing cases have in common? Give me the first hint only.

Week 7. Why does the lab say prices must be computed in code and not by the model?

Where its job stops

  • It does not edit your files or write the graded change
  • It never suggests hardcoding the public harness questions; the private harness uses different ones
  • Week 8 is the exception by design: there the exercise is to direct a coding agent, so the tutor coaches your prompt and your review, and Copilot's built-in Agent writes the code

FY26 Deploy Doctor

Ships your service to Azure and finds out why a live URL misbehaves.

Deploys after you say yes

Ask it when

  • You want to deploy an improvement
  • Your URL returns errors, or a deploy timed out
  • You need the logs for a request, or to roll back
  • Week 10: turning on the API key

What it does

  • Runs the deploy after asking, confirms the new revision is live, and scores the URL
  • Diagnoses layer by layer: the image, the revision, the running process, configuration, the model identity, your application code, and the week's feature
  • Rolls back to a previous image when a new one is broken
  • Ends with your URL, the deployed version, the score and the next step

Try saying

Deploy my Week 6 changes and tell me the score on the live URL.

My URL returns 500 for /v1/ask. The response has a request_id. Find out what happened.

The deploy cell has been waiting for the new revision for 12 minutes. What is going on?

Where its job stops

  • It asks before any command that changes Azure; read-only checks need no confirmation
  • It never deletes the resource group, the app or the Foundry resource unless you confirm after it explains what you lose

FY26 Submit Check

The last look before a deadline: does the URL you submit score what you expect?

Read-only

Ask it when

  • Before every deadline
  • After a late fix, to be sure nothing else broke

What it does

  • Runs the tests and the linter; confirms the deployed version and your student_id
  • Scores this week and every earlier week on the live URL, because the service is cumulative
  • Checks the Week 10 API key and that no secrets are staged in git
  • Reports PASS, FAIL or UNKNOWN for each item, with evidence, then the exact URL to submit

Try saying

Week 6. Am I ready to submit?

Where its job stops

  • It does not fix anything: it hands a FAIL to the Deploy Doctor or the Lab Tutor

The buttons under a reply

Agents can offer handoff buttons such as Set up my environment. They appear when the chat session runs in VS Code's Local harness. In a Copilot session, the usual default, they do not: pick the agent the reply names from the Agent dropdown yourself. Same agent, same help.

When an agent asks to run a command

VS Code shows you the exact command and waits. Read it. Allow it if you understand what it does; if you do not, ask the agent to explain first. Nothing that changes Azure should ever run without your yes.

How to ask

An agent can only work with what you tell it and what it can find. Four habits make the difference between a vague answer and the right one.

  1. Say the week."Week 6" tells the agent which lab, which checks and which files matter.
  2. Paste the exact error, not a summary.Copy the text, starting at the first line that says Error. Text beats a screenshot: the agent can search for it. Never paste secrets (see below).
  3. Name the check.Harness checks have ids such as w06.ask.citations. The id points the agent at the exact failing cases in your report.
  4. One problem per chat.Start a new chat (+) when you change topic. Long, mixed conversations make every answer worse.

Ask why, not only what. The agents are tutors as much as tools. "Why does this fix work?" turns a fix into something you understand, and understanding is what carries over to the private harness, which uses questions you have not seen.

What they will and will not do

The agents follow written rules. Knowing them tells you when to trust a step, and when to stop and ask.

They ask before changing Azure

Deploying, terraform apply and registering providers all wait for your yes. Read-only checks run without asking.

They never destroy on their own

Deleting the resource group, terraform destroy or purging Foundry happens only if you ask and confirm after they explain what you lose.

They never handle secrets

They report which keys exist in .env, never their values. Do the same: never paste keys, .env lines or Terraform state into chat.

You write the graded code

The tutor explains and hints. Week 8 is the one exception: directing a coding agent is the exercise.

The harness is the referee

Agents can be wrong. Check a claim against the harness, the lecture notes and the official docs each README links.

No shortcuts on grading

They never look for hidden grading data or edit the harness or the contract. Neither should you: the private harness uses unseen data.

Skills: what the agents know

A skill is a folder of instructions on one topic. Copilot reads its one-line description all the time and loads the full text only when your question needs it. The agents use these six; you can call them directly too.

Call a skill directly

Type / in the message box and pick a skill, for example /fy26-troubleshooting, then paste your error. Or simply ask: when your question matches a skill's description, Copilot loads it for you.

Ignore the others

Skills without the fy26- prefix belong to last year's archived labs or to instructors. You do not need them.
