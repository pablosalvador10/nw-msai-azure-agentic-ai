What an agent is, in one minute

A Copilot agent is the chat model you already know, plus three things: instructions that give it one job, tools that let it look at your files, run commands and search the official docs, and skills it loads when your question needs them. The agent is the same model; the job is what makes it useful.

One job each

A narrow job gives sharper answers and safer actions. Pablo · Start here only routes; Pablo · Fundamentals only teaches; only Will changes Azure, and only after you say yes.

Grounded in the course

They read the week's README, lecture notes, lab and your harness report before they answer, so their advice matches what you are graded on. When the course does not cover something, they check Microsoft Learn.

Plain files you can read

Each agent is one Markdown file in .github/agents/; each skill is a folder in .github/skills/. Open them: they are short.

You will build this pattern yourself. In Week 7 your service routes a support case to specialist agents, the way Pablo · Start here routes you and consults Will and Arvind. In Week 8 you write instructions for a coding agent in fy26/AGENTS.md. Reading the five agent files now is a preview of both weeks.

They are AI assistants, not people. Each one says so in its first reply, and they can be wrong. Grades, extensions and anything personal go to the course owner, Pablo Salvador Lopez.

Before the first time

Do this once. After that, the five steps in the next section are all you need, every time. If any step here fails, go to If the agents do not appear.

  1. Get CopilotVerified students get Copilot Student free through GitHub Education. Approval and activation can take a few days, so apply in the first week. Copilot Free also works, with monthly limits.
  2. Sign in in VS CodeInstall VS Code. The first time you use Chat, it asks you to sign in with GitHub: use the account that has Copilot.
  3. Open the fy26 folderClone the course (Setup, step 2). Then File, Open Folder, and pick the fy26 folder inside it. If VS Code asks whether to trust the folder or its parent, trust them: the agents live one level up, in .github/.
  4. Check the listOpen Chat, open the Agent dropdown, and look for the five agents named Pablo, Will and Arvind. Then ask Pablo · Start here your first question.

You do not need to finish Setup first. The agents need only VS Code, Copilot and the cloned course. If a later step of Setup fails, ask Will · Infra and deploy: it checks each step with you, in order.

The dropdown lists VS Code's built-in agents, such as Agent and Plan, and the five agents this repository adds. Each course agent shows a name and its job, so they are easy to spot.

Pablo · Start here

The front desk. Start here when you are lost; it brings in the experts when you need them.

Pablo · Scoring

How you are scored, how grading works, the course website, and the last look before a deadline.

Read-only

Ask it when

What it does

Will · Infra and deploy

Gets your laptop and your Azure environment working, ships your service, and finds out why a live URL misbehaves.

Asks before changing Azure

Ask it when

How to call an agent

Picking from the dropdown is the everyday way. There are three more, and the second is worth learning early: you can ask Pablo to bring the experts into one conversation.

  1. Pick it from the dropdownChoose the agent under the message box before you type. It answers every message in that chat until you switch.
  2. Ask Pablo to consultName the experts in your message to Pablo · Start here. It asks each one as a subagent, in its own context, and combines the answers into one reply.
  3. Follow a handoffIn a Local session, a button under a reply moves you to the agent it names, with a prompt filled in. In a Copilot session, pick that agent from the dropdown.
  4. Load a skill with /Type / and pick a skill, such as /fy26-harness. Its know-how goes to whichever agent you are talking to.

Ask Pablo to consult the experts

Use it when one question touches two areas. Say the week, say what you see, and name who should answer which part.

Week 6. My laptop scores 78 but my URL scores 41. Ask Will whether the deployed version matches my code, and ask Pablo · Scoring which checks differ.

Week 5. Ask Arvind which categories my service confuses most, then ask Pablo · Fundamentals for the first hint on the biggest one.

Week 10. Ask Will whether my API key is on, then ask Pablo · Scoring whether I am ready to submit.

What you see

Each consultation appears in the reply as a subagent entry with the agent's name. Select it to read what Pablo asked and what came back. The final reply says who said what.

When to go direct

Each consultation is one more model call against your Copilot allowance. When you already know who you need, pick that agent yourself. Pablo · Fundamentals and Pablo · Scoring can also ask the other experts, one fact at a time.

The buttons under a reply

Agents can offer handoff buttons such as Will: set up, deploy or fix Azure. They appear when the chat session runs in VS Code's Local harness. In a Copilot session, the usual default, they do not: pick the agent the reply names from the Agent dropdown yourself. Same agent, same help.

When an agent asks to run a command

VS Code shows you the exact command and waits. Read it. Allow it if you understand what it does; if you do not, ask the agent to explain first. Nothing that changes Azure should ever run without your yes.

How to ask

An agent can only work with what you tell it and what it can find. Four habits make the difference between a vague answer and the right one.

  1. Say the week."Week 6" tells the agent which lab, which checks and which files matter.
  2. Paste the exact error, not a summary.Copy the text, starting at the first line that says Error. Text beats a screenshot: the agent can search for it. Never paste secrets (see below).
  3. Name the check.Harness checks have ids such as w06.ask.citations. The id points the agent at the exact failing cases in your report.
  4. One problem per chat.Start a new chat (+) when you change topic. Long, mixed conversations make every answer worse.

Vibe coding with Copilot's Agent

Vibe coding means describing the change you want in plain words and letting a coding agent write it, run it and fix it while you steer. In this course the coding agent is Copilot's built-in Agent, in the same dropdown as the course agents. The course agents teach, measure and deploy; Agent writes code. Week 8 makes directing it the exercise; the habits below are the ones Week 8 teaches, and they pay off from Week 5.

You

Decide what to build, write the prompt, approve each command, read every diff, and keep only what you can explain.

Copilot's Agent

Reads AGENTS.md, plans, edits files in app/, runs the tests and the harness, and fixes what fails.

The course agents

Pablo · Fundamentals helps you understand the change and write the prompt. Pablo · Scoring reads the result. Will deploys it.

The loop

  1. Understand.Know what the change should do and which check measures it. An agent cannot build what you cannot describe; ask Pablo · Fundamentals if the idea is unclear.
  2. Plan.Commit your work first, so the agent's diff stands alone. Ask for a short plan before any edit, and read it: which files, which tests.
  3. Prompt.Pick Agent in the dropdown. Give the goal, the files, the limits, and what done means: the tests and the harness check (template below).
  4. Review.Approve only commands you understand. Read every changed file. Restore Checkpoint on a request undoes its file edits; then try a narrower prompt.
  5. Measure and ship.Run the tests, then the harness in-process. Then Will deploys and Pablo · Scoring checks the live URL.

A prompt that works

Goal, scope, limits, plan first, and a definition of done the agent can check by itself. Adapt the week, the files and the check.

Four mistakes to avoid

Keeping code you cannot explain

The private harness uses items you have not seen. If you cannot say why a change works, you cannot fix it when it fails there. Ask Agent, or Pablo · Fundamentals, to explain the diff until you can say it in three sentences.

Fitting the public items

A change that names harness ids, exact questions or expected answers raises your local score and nothing else. Reject it, and say why in your next prompt.

One giant prompt

Ask for one behavior at a time, measured by one check. Small diffs are easy to review and easy to undo; a large one hides the line that broke an earlier week.

Letting it touch Azure

A checkpoint undoes file edits, not terminal commands or deployments. Deploy with Will, who asks first and confirms the new revision.

What they will and will not do

The agents follow written rules. Knowing them tells you when to trust a step, and when to stop and ask.

Will asks before changing Azure

Deploying, terraform apply and registering providers all wait for your yes. Read-only checks run without asking. The Pablos and Arvind never change Azure.

They never destroy on their own

Deleting the resource group, terraform destroy or purging Foundry happens only if you ask and confirm after Will explains what you lose.

They never handle secrets

They report which keys exist in .env, never their values. Do the same: never paste keys, .env lines or Terraform state into chat.

You own the graded code

The course agents explain, hint and show the data; they do not write your graded change. When you vibe code with Copilot's Agent, you review every diff and can explain it.

The harness is the referee

Agents can be wrong. Check a claim against the harness, the lecture notes and the official docs each README links.

No shortcuts on grading

They never look for hidden grading data or edit the harness or the contract. Neither should you: the private harness uses unseen data.

Official docs, through MCP

The course changes slower than Azure does. So that the agents can cite current documentation, the course connects them to Microsoft Learn's MCP server, the same kind of tool server you build in Week 8.

The file fy26/.mcp.json adds one server, microsoftLearn, at https://learn.microsoft.com/api/mcp. It needs no sign-in and gives the agents two main tools: microsoft_docs_search to find relevant passages and microsoft_docs_fetch to read a whole page. When an agent uses them, the tool calls appear in the reply; expand one to see the query and the source.

The first time, VS Code may ask you to trust or start the microsoftLearn server: allow it. If it does not start, run MCP: List Servers from the Command Palette, pick microsoftLearn and choose Start Server. The agents still work without it, from the course files alone.
